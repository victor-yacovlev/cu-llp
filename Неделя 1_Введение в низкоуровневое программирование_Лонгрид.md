# Программирование на языке С, самое начало

## Что такое программа на языке C

Программа на языке C &mdash; это один или несколько файлов с исходным кодом, каждый из которых состоит из
последовательности определений и объявлений: функций, глобальных переменных, типов. Выполнение программы
всегда начинается с вызова специальной функции с именем `main` &mdash; она называется *главной функцией*
программы. Именно с неё, а не с начала файла, начинается выполнение программы.

Чтобы использовать средства стандартной библиотеки C, например функции ввода-вывода, в начале файла
подключается заголовочный файл с помощью директивы `#include`. Заголовочный файл содержит объявления
типов, переменных и функций, которые реализуют соответствующую функциональность; директива `#include`
технически представляет собой подстановку содержимого указанного файла на своё место.

### Простейшая программа на C (Hello world)

Простейшая программа на языке C, которая выводит строку текста на экран, выглядит так:

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}
```

Разберём её по частям.

Строка `#include <stdio.h>` подключает стандартный заголовочный файл `stdio.h`, в котором объявлена, среди
прочего, функция `printf`, используемая в этой программе.

Строка `int main(void)` начинает определение главной функции программы. Слово `int` означает, что функция
`main` обязана вернуть значение целого типа &mdash; так называемый *код завершения* программы. Слово `void`
в скобках означает, что функция не принимает никаких параметров.

Тело функции, заключённое в фигурные скобки `{ }`, состоит из двух операторов. Первый &mdash; вызов функции
`printf`, которая выполняет форматный вывод указанной строки на стандартный поток вывода; символ `\n` внутри
строки означает переход на новую строку. Второй &mdash; оператор `return 0`, который явно завершает работу
функции `main` и возвращает код завершения 0, означающий, что программа отработала успешно. Если оператор
`return` в функции `main` не написан явно, при достижении конца тела функции подразумевается возврат
значения 0 &mdash; поэтому в простейших программах строку `return 0;` иногда опускают.

Пусть эта программа сохранена в файле `hello.c`. Скомпилировать и запустить её можно так:

```bash
gcc -Wall -Wextra -std=gnu17 hello.c -o hello
./hello
```

В результате на экране появится строка:

```
Hello, world!
```

## Краткий обзор

Помимо базового устройства программы на C, в этом разделе мы рассмотрим четыре связанные темы.

Во-первых, как в языке C объявляются переменные, чем отличаются *локальные* переменные от *глобальных*,
и что такое *область видимости* (scope) &mdash; правило, определяющее, в какой части программы можно
использовать имя переменной. Локальная переменная существует, пока выполняется блок кода, в котором она
объявлена, и видна только внутри этого блока. Глобальная переменная существует всё время работы программы
и по умолчанию видна из любого места программы, включая другие единицы трансляции.

Во-вторых, мы рассмотрим функцию `printf`, которая выполняет форматный вывод данных на стандартный поток
вывода: как устроена форматная строка, какие бывают спецификаторы преобразования и на что нужно обращать
внимание, чтобы вывод получался корректным.

В-третьих, мы рассмотрим функцию `scanf`, которая выполняет форматный ввод данных со стандартного потока
ввода: как она использует указатели для сохранения считанных значений, как проверять успешность считывания
и какие типичные ошибки подстерегают при её использовании.

В-четвёртых, мы рассмотрим операторы ветвления (`if`/`else`) и циклы (`for`, `while`, `do while`) &mdash;
основные средства языка C для организации разного выполнения программы в зависимости от условия и для
повторяющихся вычислений.

Сначала мы кратко пройдёмся по каждой теме, а затем разберём их подробно на примерах кода на языке C.

## Объявление переменных: локальные и глобальные переменные, область видимости

Переменная в языке C объявляется указанием типа и имени:

```c
int x;
double y;
char c;
```

Такое объявление, встреченное внутри тела функции, одновременно является *определением* переменной:
оно не только вводит имя `x` в программу, но и выделяет память под переменную. Переменная может быть сразу
инициализирована значением:

```c
int x = 10;
```

Где именно объявлена переменная &mdash; внутри функции, внутри блока, или вне всех функций &mdash; определяет
и *время жизни* переменной (когда выделяется и освобождается память под неё), и её *область видимости*
(в какой части текста программы можно использовать её имя).

### Локальные переменные

Переменные, объявленные внутри тела функции или внутри любого блока, ограниченного фигурными скобками
`{ }`, называются *локальными*. Они имеют *автоматический класс памяти* (automatic storage duration):
память под них выделяется при входе в блок, в котором они объявлены, и освобождается при выходе из этого
блока. Как правило, компилятор размещает локальные переменные на стеке вызовов.

```c
#include <stdio.h>

void increment(void)
{
    int local = 0;   // локальная переменная - создаётся заново при каждом вызове функции
    local++;
    printf("local = %d\n", local);
}

int main(void)
{
    increment();
    increment();
    increment();
}
```

Результат работы программы:

```
local = 1
local = 1
local = 1
```

Каждый раз при вызове `increment` переменная `local` создаётся заново со значением 0, поэтому её значение
никогда не растёт от вызова к вызову. Важно понимать: локальная переменная, объявленная без инициализации,
не гарантированно содержит 0. Если переменная объявлена внутри функции без явного начального значения, её
значение до первого присваивания *недетерминировано* (indeterminate) &mdash; в общем случае там окажется
что-то, оставшееся в памяти от предыдущих вызовов других функций, использовавших ту же область стека.
Поэтому нельзя полагаться на то, что неинициализированная локальная переменная содержит какое-то конкретное
значение; такую переменную нужно инициализировать явно, до первого использования.

### Глобальные переменные

Переменные, объявленные вне тела любой функции, называются *глобальными*. Они имеют *статический класс
памяти* (static storage duration): память под них выделяется один раз, до начала выполнения функции `main`,
и существует всё время работы программы.

```c
#include <stdio.h>

int global_counter;          // глобальная переменная, инициализируется нулём автоматически
int global_seed = 42;        // глобальная переменная с явной инициализацией

void increment(void)
{
    global_counter++;
    printf("global_counter = %d\n", global_counter);
}

int main(void)
{
    increment();
    increment();
    increment();
    printf("seed = %d\n", global_seed);
}
```

Результат работы программы:

```
global_counter = 1
global_counter = 2
global_counter = 3
seed = 42
```

В отличие от локальных переменных, глобальная переменная `global_counter` сохраняет своё значение между
вызовами функции `increment`, потому что память под неё выделена не на время выполнения функции, а на всё
время работы программы.

Обратите внимание на важное отличие в правилах инициализации: если глобальная переменная не инициализирована
явно, она гарантированно инициализируется нулевым значением (для чисел &mdash; числовым нулём, для указателей
&mdash; нулевым указателем). Это принципиально отличается от локальных переменных, где отсутствие явной
инициализации оставляет переменную с недетерминированным значением.

### Область видимости (scope)

Область видимости &mdash; это часть текста программы, в которой можно использовать имя переменной для
обращения к ней. В языке C есть два вида области видимости, которые нужно знать в первую очередь.

*Файловая область видимости* (file scope) имеют глобальные переменные: имя такой переменной видно от точки
объявления и до конца файла (единицы трансляции), в котором она объявлена.

*Блочная область видимости* (block scope) имеют локальные переменные: имя такой переменной видно от точки
объявления и до конца блока `{ }`, в котором она объявлена, включая все вложенные блоки.

```c
#include <stdio.h>

int x = 100; // глобальная переменная x, файловая область видимости

int main(void)
{
    printf("global x = %d\n", x);

    int x = 5; // локальная переменная x скрывает глобальную на время своей области видимости
    printf("local x = %d\n", x);

    {
        int x = 10; // ещё один, более глубоко вложенный блок
        printf("inner x = %d\n", x);
    } // здесь заканчивается область видимости самой внутренней x

    printf("local x again = %d\n", x); // снова видна x из функции main
}
```

Результат работы программы:

```
global x = 100
local x = 5
inner x = 10
local x again = 5
```

Здесь одновременно существуют три разные переменные с одним и тем же именем `x`: глобальная и две локальные
на разных уровнях вложенности блоков. Это называется *сокрытием* (shadowing): пока действует область
видимости внутренней переменной `x`, обратиться по имени `x` к внешней переменной с тем же именем нельзя
&mdash; компилятор всегда выбирает переменную из самой внутренней области видимости, в которой это имя
объявлено. Так, во второй строке вывода мы уже не можем обратиться к глобальной `x` просто по имени `x`,
а в блоке с `inner x` мы не можем просто по имени `x` обратиться к локальной переменной `main`.

Сокрытие переменных, особенно непреднамеренное, является источником ошибок: легко перепутать, к какой
именно переменной идёт обращение в конкретной строке кода. Компилятор GCC умеет предупреждать о таких
ситуациях, если добавить опцию `-Wshadow`:

```
ex2_shadow.c: In function 'main':
ex2_shadow.c:8:9: warning: declaration of 'x' shadows a global declaration [-Wshadow]
    8 |     int x = 5;
      |         ^
ex2_shadow.c:3:5: note: shadowed declaration is here
    3 | int x = 100;
      |     ^
```

Мы рекомендуем не полагаться на сокрытие переменных и по возможности избегать повторного использования
одинаковых имён для разных переменных в пределах одной функции.

### Локальные переменные, сохраняющие значение между вызовами

Из общего правила, что локальные переменные создаются заново при каждом входе в блок, есть управляемое
исключение. Если локальную переменную объявить с ключевым словом `static`, у неё, как и у глобальной
переменной, будет статический класс памяти: память под неё выделяется один раз, а инициализация происходит
только один раз, до первого выполнения этой точки программы. При этом область видимости имени переменной
остаётся блочной &mdash; переменная по-прежнему видна только внутри того блока, где она объявлена.

```c
#include <stdio.h>

int next_id(void)
{
    static int counter = 0;   // инициализируется один раз, до первого вызова
    return counter++;
}

int main(void)
{
    for (int i = 0; i < 3; ++i) {
        printf("id: %d\n", next_id());
    }
}
```

Результат работы программы:

```
id: 0
id: 1
id: 2
```

Переменная `counter` объявлена внутри функции `next_id`, поэтому её имя недоступно нигде, кроме тела этой
функции &mdash; в этом смысле она ведёт себя как локальная переменная. Но, в отличие от обычной локальной
переменной, её значение сохраняется между вызовами функции, потому что модификатор `static` даёт ей
статический класс памяти, как у глобальной переменной.

## Вывод данных: функция printf

Функция `printf` выполняет форматный вывод данных на стандартный поток вывода `stdout`. Её объявление
находится в заголовочном файле `<stdio.h>`:

```c
int printf(const char *format, ...);
```

Первый аргумент &mdash; форматная строка, задающая, как должны быть преобразованы и выведены остальные
аргументы. Форматная строка состоит из обычного текста, который выводится как есть, и *спецификаций
преобразования*, каждая из которых начинается с символа `%` и указывает, какое значение и как нужно
вывести на этом месте. Функция возвращает количество выведенных байт либо отрицательное значение в случае
ошибки.

### Основные спецификаторы преобразования

| Спецификатор | Тип аргумента | Что выводится |
| - | - | - |
| `%d`, `%i` | `int` | Целое число в десятичном виде со знаком |
| `%u` | `unsigned int` | Целое число в десятичном виде без знака |
| `%x`, `%X` | `unsigned int` | Целое число в шестнадцатеричном виде (строчными или заглавными буквами) |
| `%o` | `unsigned int` | Целое число в восьмеричном виде |
| `%f` | `double` | Вещественное число в виде `123.456000` |
| `%e`, `%E` | `double` | Вещественное число в экспоненциальном виде `1.234560e+02` |
| `%g`, `%G` | `double` | Вещественное число, компилятор сам выбирает `%f` или `%e` в зависимости от величины числа |
| `%c` | `int` (значение `char`) | Один символ |
| `%s` | `const char *` | Строка, завершающаяся нулевым байтом |
| `%p` | `void *` | Значение указателя в шестнадцатеричном виде |
| `%%` | &mdash; | Выводит символ `%` буквально, аргумент не требуется |

### Флаги, ширина и точность

Между символом `%` и буквой спецификатора можно указать дополнительные параметры форматирования:
флаги, минимальную ширину поля и точность.

```c
#include <stdio.h>

int main(void)
{
    int i = -42;
    double d = 3.14159265358979;
    const char *s = "hello";

    printf("[%d]\n", i);       // [-42]           обычный вывод
    printf("[%5d]\n", i);      // [  -42]         минимальная ширина поля 5, выравнивание по правому краю
    printf("[%-5d]\n", i);     // [-42  ]         флаг '-' - выравнивание по левому краю
    printf("[%05d]\n", i);     // [-0042]         флаг '0' - дополнение нулями вместо пробелов
    printf("[%.2f]\n", d);     // [3.14]          точность .2 - два знака после запятой
    printf("[%10.2f]\n", d);   // [      3.14]    ширина 10 и точность 2 одновременно
    printf("[%.3s]\n", s);     // [hel]           точность у строки ограничивает число выводимых символов
}
```

Ширина поля задаёт *минимальное* количество символов, которое займёт значение в выводе; если значение
короче, оно дополняется пробелами (или нулями, если указан флаг `0`) слева (или справа, если указан флаг
`-`). Если значение длиннее указанной ширины, ширина не усекает вывод. Точность после числа с плавающей
точкой задаёт количество знаков после десятичной точки, а точность у строки, наоборот, задаёт максимальное
число выводимых символов.

### Модификаторы длины

Целочисленные спецификаторы `%d`, `%u`, `%x` и другие по умолчанию рассчитаны на аргументы типа `int` или
`unsigned int`. Чтобы вывести значение другого целочисленного типа, перед буквой спецификатора добавляется
модификатор длины.

| Модификатор | Тип аргумента (для `%d`) | Пример |
| - | - | - |
| `hh` | `signed char` / `unsigned char` | `%hhd` |
| `h` | `short` / `unsigned short` | `%hd` |
| (нет) | `int` / `unsigned int` | `%d` |
| `l` | `long` / `unsigned long` | `%ld` |
| `ll` | `long long` / `unsigned long long` | `%lld` |
| `z` | `size_t` (беззнаковый) | `%zu` |
| `t` | `ptrdiff_t` (знаковый) | `%td` |

Для вещественных чисел модификатор `l` перед `f`, `e`, `g` в функциях *вывода* ничего не меняет: и `float`,
и `double`, переданные в `printf` через многоточие, всегда продвигаются до `double`. Модификатор `L` перед
`f`, `e`, `g` используется для типа `long double`.

```c
#include <stdio.h>

int main(void)
{
    long l = 123456789012L;
    printf("[%ld]\n", l); // [123456789012]
}
```

### Проверка форматной строки компилятором

Одна из типичных ошибок при использовании `printf` &mdash; несоответствие спецификатора и фактического
типа переданного аргумента, например использование `%d` для аргумента типа `long`. Такое несоответствие
&mdash; неопределённое поведение. Однако компилятор GCC умеет статически анализировать форматную строку и
сверять её со списком фактических аргументов, если форматная строка известна на этапе компиляции (то есть
задана константным строковым литералом, а не вычисляется во время работы программы). Эта проверка
включается опцией `-Wformat`, которая, в свою очередь, включается опцией `-Wall`. Поэтому программы всегда
следует компилировать с опциями `-Wall -Werror`, чтобы такие ошибки превращались в ошибку компиляции, а не
оставались незамеченными.

## Считывание данных: функция scanf

Функция `scanf` выполняет форматный ввод данных со стандартного потока ввода `stdin`. Её объявление также
находится в `<stdio.h>`:

```c
int scanf(const char *format, ...);
```

В отличие от `printf`, аргументы, следующие за форматной строкой в `scanf`, должны быть *указателями* на
переменные, в которые нужно записать считанные значения &mdash; ведь `scanf` должна не прочитать значения
этих переменных, а изменить их.

```c
#include <stdio.h>

int main(void)
{
    int a, b;
    int r = scanf("%d %d", &a, &b);
    if (r != 2) {
        fprintf(stderr, "%s: expected two integers, got %d\n", __FUNCTION__, r);
        return 1;
    }
    printf("a + b = %d\n", a + b);
    return 0;
}
```

Если на стандартный поток ввода подать строку `3 4`, программа выведет `a + b = 7` и завершится с кодом 0.
Если же подать строку `3 x`, значение `x` не удастся распознать как второе целое число, `scanf` считает
только один аргумент, вернёт значение 1, и программа выведет на поток ошибок сообщение `main: expected two
integers, got 1` и завершится с кодом 1.

### Проверка возвращаемого значения

Функция `scanf` возвращает количество аргументов, для которых удалось успешно считать и сохранить значение.
Если разбор самого первого аргумента завершился неудачно, возвращается 0. Если входные данные закончились
или произошла ошибка ввода до того, как был обработан хотя бы один аргумент, возвращается специальное
значение `EOF`. **Использование `scanf` без проверки возвращаемого значения &mdash; это ошибка.** Без такой
проверки программа не может отличить ситуацию, когда переменные `a` и `b` из примера выше действительно
были успешно заполнены, от ситуации, когда во входных данных были не числа, а что-то другое, и переменные
остались неопределёнными.

Большинство форматных спецификаторов чтения, например `%d` или `%f`, перед считыванием значения сначала
пропускают все пробельные символы (пробел, табуляция, перевод строки) во входном потоке. Поэтому отдельно
заботиться о пропуске пробелов и переводов строк между числами, как правило, не требуется.

### Считывание строк с помощью %s и переполнение буфера

Спецификатор `%s` требует особой осторожности. Он считывает последовательность непробельных символов в
массив `char`, переданный по указателю, и завершает её нулевым байтом. Проблема в том, что без
дополнительных указаний `scanf` не знает размера принимающего массива и запишет туда столько байт, сколько
встретит во входном потоке до ближайшего пробельного символа, что может привести к выходу за границы
массива.

```c
#include <stdio.h>

int main(void)
{
    char buf[8];
    int r = scanf("%7s", buf); // не более 7 символов + завершающий нулевой байт = ровно 8 байт
    if (r != 1) return 1;
    printf("buf = '%s'\n", buf);
    return 0;
}
```

Если на вход подать строку `abcdefghij`, программа выведет `buf = 'abcdefg'`: указание ширины поля `7` в
`%7s` ограничивает число считываемых символов семью, оставляя место для завершающего нулевого байта в
восьмибайтном массиве `buf`. Без указания ширины поля вызов `scanf("%s", buf)` при более длинной входной
строке привёл бы к записи за пределы массива `buf` &mdash; неопределённому поведению, которое на практике
часто оказывается серьёзной уязвимостью программы.

### Типичная ошибка: смешивание scanf с построчным чтением

Спецификаторы вроде `%d` не считывают завершающий перевод строки после числа &mdash; он остаётся во входном
потоке необработанным. Если после `scanf("%d", ...)` вызвать функцию, ожидающую чтение целой строки,
например `fgets`, эта функция немедленно наткнётся на оставшийся символ `'\n'` и вернёт пустую строку,
даже не дожидаясь ввода пользователя.

```c
#include <stdio.h>

int main(void)
{
    int n;
    char name[64];

    int r1 = scanf("%d", &n);                     // после числа во входном потоке остаётся '\n'
    if (r1 != 1) return 1;

    char *r2 = fgets(name, sizeof(name), stdin);   // считывает оставшийся '\n' как пустую строку!
    if (!r2) return 1;

    printf("n = %d, name = '%s'\n", n, name);
    return 0;
}
```

Если на вход подать `5`, затем на следующей строке `Alice`, интуитивно ожидается вывод `n = 5, name =
'Alice'`. На самом деле программа выведет `n = 5, name = ''` (пустая строка): `fgets` считал не введённое
имя, а перевод строки, оставшийся во входном потоке от предыдущего вызова `scanf`.

Чтобы избежать этой ошибки, лишний символ перевода строки нужно явно пропустить перед вызовом `fgets`,
например так:

```c
#include <stdio.h>

int main(void)
{
    int n;
    char name[64];

    int r1 = scanf("%d", &n);
    if (r1 != 1) return 1;

    int c;
    while ((c = getchar()) != '\n' && c != EOF) {
        // пропускаем остаток строки, включая сам '\n'
    }

    char *r2 = fgets(name, sizeof(name), stdin);
    if (!r2) return 1;

    printf("n = %d, name = '%s'\n", n, name);
    return 0;
}
```

Теперь при том же входе программа выведет `n = 5, name = 'Alice'` (со следующим за именем символом перевода
строки, который сохраняет в буфере сам `fgets`). Из-за подобных тонкостей, если в одной программе требуется
и построчное, и форматное чтение, стоит заранее продумать, в каком порядке и какими функциями будет
выполняться ввод, чтобы избежать неожиданно оставшихся во входном потоке символов.

## Ветвление и циклы

Рассмотрим простую задачу: для каждого числа от 1 до 20 вывести на экран либо само число, либо слово
`Fizz`, если число делится на 3, либо слово `Buzz`, если число делится на 5, либо слово `FizzBuzz`, если
число делится и на 3, и на 5 одновременно.

```c
#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 20; ++i) {
        if (i % 15 == 0) {
            printf("FizzBuzz\n");
        } else if (i % 3 == 0) {
            printf("Fizz\n");
        } else if (i % 5 == 0) {
            printf("Buzz\n");
        } else {
            printf("%d\n", i);
        }
    }
    return 0;
}
```

Цикл `for (int i = 1; i <= 20; ++i)` перебирает числа от 1 до 20 включительно. Внутри цикла оператор `if`
с цепочкой `else if` проверяет условия по очереди: сначала делимость на 15 (то есть одновременно на 3 и на
5), и только если это условие ложно, проверяется делимость на 3, затем на 5; если ни одно из условий не
выполнено, выполняется ветка `else`. Порядок проверок здесь важен: если бы мы проверяли делимость на 3
раньше делимости на 15, то для чисел, кратных 15, выводилось бы `Fizz`, а не `FizzBuzz`, потому что после
первого совпавшего условия в цепочке `if`/`else if` остальные условия не проверяются.

Результат работы программы:

```
1
2
Fizz
4
Buzz
Fizz
7
8
Fizz
Buzz
11
Fizz
13
14
FizzBuzz
16
17
Fizz
19
Buzz
```

Рассмотрим ещё одну простую задачу, иллюстрирующую цикл `do while`: посчитать количество десятичных цифр
в числе.

```c
#include <stdio.h>

int main(void)
{
    int n = 12345;
    int count = 0;
    int tmp = n;
    do {
        count++;
        tmp /= 10;
    } while (tmp != 0);
    printf("%d has %d digits\n", n, count);
    return 0;
}
```

Результат работы программы:

```
12345 has 5 digits
```

Здесь удобен именно цикл `do while`, а не `while`, потому что тело цикла должно выполниться хотя бы один
раз, даже если исходное число равно 0 (у числа 0 одна цифра). Цикл `while (expr) statement` сначала
проверяет условие и только потом, если оно истинно, выполняет тело цикла, поэтому для числа 0 обычный
`while`-цикл, начинающийся с проверки `tmp != 0`, не выполнился бы ни разу, и результат `count` остался бы
равным 0, хотя правильный ответ &mdash; одна цифра. Цикл `do statement while (expr);`, напротив, сначала
выполняет тело цикла и только потом проверяет условие, поэтому тело гарантированно выполняется хотя бы
один раз.

## Целочисленные типы данных и операторы

### Целочисленные типы

В языке C есть несколько целочисленных типов, отличающихся диапазоном представимых значений. У каждого
типа есть знаковый вариант, допускающий отрицательные значения, и беззнаковый вариант с модификатором
`unsigned`, допускающий только неотрицательные значения, но зато с бóльшим положительным диапазоном.

| Тип | Типичный размер | Типичный диапазон (знаковый) |
| - | - | - |
| `char` | 1 байт | `[-128; 127]` |
| `short` | 2 байта | `[-32768; 32767]` |
| `int` | 4 байта | `[-2147483648; 2147483647]` |
| `long` | 4 или 8 байт | зависит от платформы |
| `long long` | 8 байт | `[-9223372036854775808; 9223372036854775807]` |

Точный размер типов `int` и `long`, вообще говоря, зависит от платформы и компилятора, но размер типа
`long long` гарантированно не меньше 8 байт. Поэтому если требуется, чтобы значение переменной, например
результат накопления суммы большого количества чисел, гарантированно поместилось в переменную без
переполнения независимо от платформы, для такой переменной стоит выбирать тип `long long` &mdash; при
условии, конечно, что заранее известно, что итоговое значение действительно уместится в его диапазон.

### Операторы над целыми числами

Над значениями целых типов определены обычные арифметические операторы: сложение `+`, вычитание `-`,
умножение `*`, деление `/` и взятие остатка от деления `%`.

Важно помнить, что деление `/`, если оба операнда имеют целый тип, выполняется как *целочисленное
деление*: дробная часть результата отбрасывается (усечение к нулю), а не округляется. Например, выражение
`7 / 2` даёт значение `3`, а не `3.5`. Оператор `%` дополняет деление: он возвращает остаток от деления,
такой что `(a / b) * b + a % b == a`. Например, `7 % 2` даёт значение `1`.

```c
#include <stdio.h>

int main(void)
{
    printf("%d\n", 7 / 2);  // 3  - целочисленное деление, дробная часть отброшена
    printf("%d\n", 7 % 2);  // 1  - остаток от деления
}
```

Кроме обычного оператора присваивания `=`, существуют составные операторы присваивания `+=`, `-=`, `*=`,
`/=`, `%=`, которые изменяют значение переменной на месте. Например, запись `sum += value;` эквивалентна
записи `sum = sum + value;`, но короче и, как правило, понятнее читается.

Если в арифметическом выражении участвуют операнды разных целых типов, например `long long` и `int`,
компилятор неявно преобразует операнд более узкого типа к более широкому типу, чтобы выполнить операцию
без потери значащих бит &mdash; в данном случае значение типа `int` будет преобразовано к `long long`
перед сложением. Поэтому, если в переменной типа `long long` накапливается сумма значений типа `int`,
эта сумма пересчитывается корректно, даже если сама по себе переменная типа `int` не смогла бы вместить
такую сумму.

### Разбор программы: среднее арифметическое чисел, переданных в командной строке

Рассмотрим программу, которая принимает произвольное количество целых чисел в виде аргументов командной
строки, суммирует их и выводит на экран сумму и среднее арифметическое. Условимся, что входные данные
таковы, что накапливаемая сумма гарантированно поместится в тип `long long`.

Чтобы программа могла получить доступ к аргументам командной строки, функция `main` должна быть объявлена
с двумя параметрами:

```c
int main(int argc, char *argv[])
```

Параметр `argc` (от *argument count*) содержит количество аргументов командной строки, включая имя самой
программы. Параметр `argv` (от *argument vector*) &mdash; это массив строк: `argv[0]` содержит имя, с
которым была запущена программа, а `argv[1]`, ..., `argv[argc-1]` содержат сами аргументы, переданные
пользователем.

```c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <string.h>

int main(int argc, char *argv[])
{
    if (argc < 2) {
        fprintf(stderr, "%s: usage: %s NUM...\n", __FUNCTION__, argv[0]);
        return 1;
    }

    long long sum = 0;      // накапливаем сумму - гарантированно поместится в long long
    int count = argc - 1;   // количество чисел, переданных в командной строке

    for (int i = 1; i < argc; ++i) {
        char *eptr;
        errno = 0;
        long value = strtol(argv[i], &eptr, 10);
        if (eptr == argv[i] || *eptr || errno) {
            fprintf(stderr, "%s: '%s' is not a valid integer\n", __FUNCTION__, argv[i]);
            return 1;
        }
        sum += value;        // long неявно преобразуется в long long, потери не будет
    }

    long long quotient = sum / count;      // целочисленное частное
    long long remainder = sum % count;     // остаток от деления
    double average = (double) sum / count; // точное среднее

    printf("sum = %lld\n", sum);
    printf("count = %d\n", count);
    printf("average (integer division) = %lld, remainder = %lld\n", quotient, remainder);
    printf("average (exact) = %f\n", average);

    return 0;
}
```

Разберём программу по частям.

Сначала проверяется, что программе передан хотя бы один аргумент (`argc < 2` означает, что кроме имени
программы других аргументов нет). Если аргументов нет, в поток ошибок выводится сообщение о правильном
использовании программы, и функция `main` завершается с ненулевым кодом, сигнализирующим об ошибке.

Далее в цикле по всем аргументам, кроме нулевого (то есть по `argv[1]`, ..., `argv[argc-1]`), каждая
строка преобразуется в целое число функцией `strtol`. Указатель `eptr` после вызова `strtol` указывает
на первый байт строки, который не был распознан как часть числа; если этот байт не нулевой, значит, в
конце строки остался “мусор”, и строку нельзя считать корректным числом. Переменная `errno` проверяется
на случай, если число слишком велико и не поместилось в тип `long`. Только если оба условия в порядке,
считанное значение добавляется к накапливаемой сумме `sum`.

Обратите внимание, что каждое отдельное число разбирается в переменную типа `long`, а накапливается сумма
в переменной типа `long long`: при выполнении `sum += value` значение `value` неявно преобразуется к типу
`long long`, поэтому даже если отдельные числа велики, сложение выполняется без потери точности, а
переполниться может только сама сумма &mdash; но по условию задачи она гарантированно умещается в тип
`long long`.

В конце программы вычисляются целочисленное частное и остаток от деления суммы на количество чисел с
помощью операторов `/` и `%`, а также точное среднее значение с помощью деления `(double) sum / count`.
Явное приведение типа `(double)` здесь обязательно: если бы мы написали `sum / count`, оба операнда имели
бы целый тип, и деление выполнилось бы как целочисленное, отбросив дробную часть результата. Приведение
одного из операндов к типу `double` заставляет компилятор выполнить деление как вещественное, с сохранением
дробной части.

Если запустить программу с аргументами `10 20 30 -5`, она выведет:

```
sum = 55
count = 4
average (integer division) = 13, remainder = 3
average (exact) = 13.750000
```

Если же передать аргумент, не являющийся корректным числом, например `10 abc 30`, программа выведет
сообщение об ошибке и завершится с ненулевым кодом:

```
main: 'abc' is not a valid integer
```

## Оператор switch, операторы break, continue и goto

Кроме `if`/`else` и циклов `for`, `while`, `do while`, в языке C есть ещё несколько операторов управления
ходом выполнения программы: оператор множественного выбора `switch` и операторы `break`, `continue`,
`goto`, которые досрочно меняют обычный порядок выполнения циклов или передают управление в произвольное
место функции.

### Оператор switch

Оператор `switch` сравнивает значение выражения с несколькими константами и передаёт управление в ту ветку
`case`, значение которой совпало. Это удобная альтернатива длинной цепочке `if`/`else if`, когда сравнение
всегда идёт с одной и той же переменной.

```c
#include <stdio.h>

int main(void)
{
    for (char c = 'a'; c <= 'f'; ++c) {
        switch (c) {
        case 'a':
        case 'e':
            printf("%c: vowel\n", c);
            break;
        case 'b':
        case 'c':
        case 'd':
        case 'f':
            printf("%c: consonant\n", c);
            break;
        default:
            printf("%c: other\n", c);
            break;
        }
    }
    return 0;
}
```

Результат работы программы:

```
a: vowel
b: consonant
c: consonant
d: consonant
e: vowel
f: consonant
```

Метка `case значение:` отмечает точку в теле `switch`, в которую передаётся управление, если вычисленное
значение выражения в `switch (...)` равно этому значению; значение после `case` обязано быть константой,
известной на этапе компиляции. Метка `default:` необязательна и отмечает точку, в которую передаётся
управление, если ни одна из меток `case` не совпала. Несколько меток `case`, идущих подряд без операторов
между ними, как `case 'a':` и `case 'e':` в примере выше, означают, что оба значения приводят к выполнению
одного и того же тела &mdash; это стандартный способ сгруппировать несколько значений с общей обработкой.

Оператор `break` внутри `switch` завершает выполнение `switch` целиком и передаёт управление за его
закрывающую скобку. **Про `break` в конце каждой ветки `case` легко забыть, а забывать нельзя**: без
`break` выполнение не останавливается на границе ветки, а *проваливается* (fall through) в следующую по
тексту ветку `case`, независимо от того, совпало её значение или нет.

```c
#include <stdio.h>

int main(void)
{
    int day = 6;
    switch (day) {
    case 6:
    case 7:
        printf("weekend\n");
    default:
        printf("day number: %d\n", day);
    }
    return 0;
}
```

При компиляции с `-Wextra` GCC предупреждает о таком непреднамеренном проваливании:

```
switch2.c: In function ‘main’:
switch2.c:9:9: warning: this statement may fall through [-Wimplicit-fallthrough=]
    9 |         printf("weekend\n");
      |         ^~~~~~~~~~~~~~~~~~~
switch2.c:10:5: note: here
   10 |     default:
      |     ^~~~~~~
```

Результат работы программы:

```
weekend
day number: 6
```

Здесь `day == 6` совпадает с `case 6`, но так как в ветке `case 6` нет ни одного оператора, выполнение сразу
проваливается в `case 7`, где выводится `weekend`; а поскольку и в `case 7` нет `break`, выполнение
проваливается дальше, в `default`, и дополнительно выводится `day number: 6`. Если такое поведение задумано
намеренно (как пустое проваливание `case 6` в `case 7` в этом же примере), явных операторов между метками
быть не должно &mdash; тогда GCC не считает это подозрительным местом и не предупреждает. Но проваливание
через ветку, где что-то выводится или вычисляется, как в примере с `weekend`, почти всегда является ошибкой,
поэтому правило простое: в конце каждой ветки `case`, кроме случаев намеренной группировки пустых меток,
должен стоять `break` (или `return`, если ветка `switch` завершает функцию).

### Операторы break и continue в циклах

Оператор `break` внутри цикла (`for`, `while` или `do while`) немедленно завершает этот цикл, независимо
от того, выполнено ли его условие. Оператор `continue`, в отличие от него, не завершает цикл, а пропускает
оставшуюся часть тела текущей итерации и сразу переходит к проверке условия следующей итерации (в цикле
`for` перед этим ещё выполняется шаг приращения).

```c
#include <stdio.h>

int main(void)
{
    printf("continue: числа от 1 до 10, кроме кратных 3:\n");
    for (int i = 1; i <= 10; ++i) {
        if (i % 3 == 0) {
            continue;   // пропускаем оставшуюся часть тела цикла и переходим к следующей итерации
        }
        printf("%d\n", i);
    }

    printf("break: ищем первое число, чей квадрат больше 50\n");
    for (int i = 1; i <= 100; ++i) {
        if (i * i > 50) {
            printf("found: %d (%d^2 = %d)\n", i, i, i * i);
            break;      // досрочно прерываем цикл, дальнейшие итерации не нужны
        }
    }
    return 0;
}
```

Результат работы программы:

```
continue: числа от 1 до 10, кроме кратных 3:
1
2
4
5
7
8
10
break: ищем первое число, чей квадрат больше 50
found: 8 (8^2 = 64)
```

Важная тонкость: и `break`, и `continue` относятся к *самому близкому* окружающему их циклу (или, в случае
`break`, ещё и к самому близкому окружающему `switch`, если он ближе цикла). В частности, если `break`
находится внутри `switch`, который, в свою очередь, находится внутри цикла, такой `break` выходит только
из `switch`, а не из цикла:

```c
#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 5; ++i) {
        switch (i) {
        case 3:
            printf("i == 3: break внутри switch\n");
            break;   // выходит только из switch, цикл for продолжает работу
        default:
            printf("i = %d\n", i);
            break;
        }
    }
    printf("цикл завершился естественным образом, все 5 итераций выполнены\n");
    return 0;
}
```

Результат работы программы:

```
i = 1
i = 2
i == 3: break внутри switch
i = 4
i = 5
цикл завершился естественным образом, все 5 итераций выполнены
```

Хотя `break` сработал на итерации `i == 3`, цикл `for` не прервался и благополучно дошёл до `i == 5`,
потому что этот `break` относится к `switch`, а не к циклу.

### Оператор goto и метки

Оператор `goto метка;` безусловно передаёт управление в точку функции, отмеченную `метка:`. Метка должна
находиться в той же функции, что и сам `goto`. В большинстве ситуаций использования `goto` следует избегать
&mdash; тех же результатов почти всегда можно добиться обычными циклами, `break`, `continue` и структурным
ветвлением, а код без `goto`, как правило, легче читать и сопровождать.

Одна из немногих распространённых и оправданных ситуаций для `goto` в C &mdash; выход сразу из нескольких
вложенных циклов, потому что `break` умеет прерывать только один, самый близкий к нему цикл.

```c
#include <stdio.h>

int main(void)
{
    int grid[3][3] = {
        {1, 2, 3},
        {4, 5, 6},
        {7, 8, 9}
    };
    int target = 6;
    int found_row = -1, found_col = -1;

    for (int row = 0; row < 3; ++row) {
        for (int col = 0; col < 3; ++col) {
            if (grid[row][col] == target) {
                found_row = row;
                found_col = col;
                goto done;   // сразу выходим из обоих вложенных циклов
            }
        }
    }

done:
    if (found_row >= 0) {
        printf("found %d at [%d][%d]\n", target, found_row, found_col);
    } else {
        printf("%d not found\n", target);
    }
    return 0;
}
```

Результат работы программы:

```
found 6 at [1][2]
```

Без `goto` для выхода сразу из обоих циклов пришлось бы заводить дополнительную переменную-флаг и
проверять её условием во внешнем цикле, либо выносить поиск в отдельную функцию и использовать `return`.
`goto` в подобном случае &mdash; не обход правил языка, а его штатное, документированное средство именно
для такой ситуации: одна метка `done:` после обоих циклов и один `goto done;` в точке находки читаются
проще, чем дополнительная переменная-флаг, размножающая проверки во внешнем цикле.

## Неопределённое поведение

По ходу этого файла нам уже несколько раз встречалось словосочетание "неопределённое поведение"
(undefined behavior, UB): при обращении к неинициализированной локальной переменной, при переполнении
буфера в `scanf("%s", ...)` без указания ширины поля. Разберём это понятие отдельно и подробнее, потому что
оно принципиально важно для языка C.

### Что такое неопределённое поведение

Стандарт языка C для некоторых конструкций и ситуаций не накладывает вообще никаких требований на
поведение программы. Это и называется неопределённым поведением: если программа хотя бы раз попадает в
такую ситуацию, стандарт не гарантирует ничего &mdash; ни конкретного результата, ни даже того, что
программа продолжит вести себя предсказуемо в остальных частях. На практике это может проявляться как
угодно: программа может выдать неожиданное значение, аварийно завершиться, отработать "как ожидалось" на
одной платформе или при одних настройках оптимизации и сломаться на других, или даже вести себя так, будто
предшествующих ей строк кода не было вовсе.

Причина, по которой в языке C неопределённое поведение вообще существует, а не запрещено полностью, &mdash;
производительность. Компилятор C, в отличие от компиляторов многих других языков, не обязан вставлять
проверки (границ массива, переполнения, деления на ноль и так далее) на каждую потенциально опасную
операцию. Считается, что программист сам отвечает за то, чтобы такие ситуации не возникали, а компилятор
вправе исходить из предположения, что неопределённого поведения в программе не происходит, и агрессивно
оптимизировать код на основе этого предположения. Именно поэтому одна и та же программа с UB может вести
себя по-разному в зависимости от опций оптимизации: компилятор, полагая, что до неопределённой ситуации
дело никогда не доходит, иногда переставляет местами, упрощает или вовсе выбрасывает часть кода.

Неопределённое поведение стоит отличать от двух похожих, но менее опасных понятий. *Не определённое до
конца поведение* (unspecified behavior) &mdash; это ситуация, когда стандарт разрешает несколько вариантов
поведения, не указывая, какой именно выберет конкретный компилятор, но каждый из этих вариантов сам по себе
корректен и безопасен. *Поведение, определяемое реализацией* (implementation-defined behavior) &mdash; это
частный случай unspecified behavior, при котором каждая конкретная реализация компилятора обязана
задокументировать, какой именно вариант она выбирает, и придерживаться его. Пример implementation-defined
behavior, который мы уже видели в этом файле: точный размер типов `int` и `long` в байтах не фиксирован
стандартом, но каждый конкретный компилятор для конкретной платформы использует определённый, задокументированный
размер.

### Пример: неопределённый порядок вычисления и неопределённое поведение — это разные вещи

Стандарт C не фиксирует порядок, в котором вычисляются аргументы функции перед вызовом (в том числе аргументы
`printf`). Сам по себе этот факт &mdash; unspecified behavior, а не UB: если каждый аргумент только читает
или изменяет *свою собственную* переменную, программа остаётся корректной независимо от того, в каком
порядке компилятор вычислит аргументы.

```c
#include <stdio.h>

int main(void)
{
    int i = 0, j = 100;
    printf("%d %d\n", i++, j--);   // порядок вычисления аргументов не определён, но UB здесь нет: i и j разные объекты
    printf("i = %d, j = %d\n", i, j);
    return 0;
}
```

Результат работы программы:

```
0 100
i = 1, j = 99
```

Здесь нельзя быть уверенным, в каком порядке компилятор вычислит `i++` и `j--` &mdash; это и есть
unspecified behavior, полагаться на конкретный порядок в переносимом коде нельзя. Но, поскольку `i++`
трогает только `i`, а `j--` только `j`, к какому бы порядку компилятор ни прибегнул, результат программы
одинаков и корректен: после выполнения строки `i` равно 1, а `j` равно 99.

Ситуация меняется, если оба аргумента изменяют *одну и ту же* переменную:

```c
#include <stdio.h>

int main(void)
{
    int i = 0;
    printf("%d %d\n", i++, i++);   // неопределённое поведение: два изменения i, не упорядоченные друг относительно друга
    return 0;
}
```

Компилятор GCC отказывается компилировать этот код с опцией `-Wall` (в составе которой включено
`-Wsequence-point`), сообщая об ошибке:

```
unspecified.c: In function ‘main’:
unspecified.c:6:29: error: operation on ‘i’ may be undefined [-Werror=sequence-point]
    6 |     printf("%d %d\n", i++, i++);
      |                            ~^~
```

Здесь оба аргумента изменяют одну и ту же переменную `i`, и стандарт не гарантирует, в каком порядке (и
относительно чтения значения `i` для каждого из двух `%d`) это произойдёт. Это уже не просто неопределённый
порядок вычисления, а настоящее неопределённое поведение: правило языка прямо говорит, что если два
изменения одного и того же объекта не упорядочены друг относительно друга явным образом, поведение
программы не определено. GCC специально распознаёт этот конкретный, часто встречающийся случай и
предупреждает о нём ещё на этапе компиляции, но в общем случае компилятор не обязан обнаруживать
неопределённое поведение и предупреждать о нём.

### Переполнение целого числа со знаком

Другой распространённый источник неопределённого поведения, прямо связанный с материалом этого файла,
&mdash; переполнение целого числа *со знаком* при арифметических операциях. Стандарт C не определяет, что
происходит, когда результат сложения, вычитания или умножения значений подписанного целого типа выходит за
границы представимого диапазона.

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    int a = INT_MAX;
    int b = a + 1;   // переполнение int со знаком - неопределённое поведение
    printf("a = %d, a + 1 = %d\n", a, b);
    return 0;
}
```

При обычной компиляции (без специальных инструментов) программа, скорее всего, выведет то, что интуитивно
ожидается от "заворачивания" числа через границу диапазона:

```
a = 2147483647, a + 1 = -2147483648
```

Но полагаться на этот конкретный результат нельзя: он не гарантирован стандартом, а лишь совпадает с
поведением, типичным для представления чисel в дополнительном коде на большинстве платформ. Чтобы явно
обнаружить сам факт неопределённого поведения (а не просто увидеть его правдоподобный побочный эффект),
используется UndefinedBehaviorSanitizer &mdash; инструмент компилятора, включаемый опцией `-fsanitize=undefined`:

```bash
gcc -Wall -Wextra -std=gnu17 -fsanitize=undefined -g overflow.c -o overflow_ubsan
./overflow_ubsan
```

Результат работы программы:

```
overflow.c:7:9: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
a = 2147483647, a + 1 = -2147483648
```

UBSan обнаруживает переполнение прямо в момент его возникновения и выводит диагностическое сообщение с
указанием файла и строки, но по умолчанию не останавливает программу &mdash; после диагностики выполнение
продолжается, и программа всё равно выводит то же "правдоподобное" значение `-2147483648`, что и без
sanitizer. Заметим, что арифметика с переполнением для *беззнаковых* целых типов (`unsigned`), в отличие от
знаковых, определена стандартом полностью: она всегда выполняется по модулю $2^n$, где $n$ &mdash; ширина
типа в битах, и UB здесь не возникает.

### Деление на ноль

Ещё один пример UB, напрямую связанный с целочисленными операторами этого файла, &mdash; целочисленное
деление или взятие остатка от деления на ноль.

```c
#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 0;
    int c = a / b;   // деление на ноль для целых чисел - неопределённое поведение
    printf("c = %d\n", c);
    return 0;
}
```

При запуске программы, собранной с `-fsanitize=undefined`, получаем:

```
divzero.c:7:15: runtime error: division by zero
```

и сразу вслед за этим диагностическим сообщением сама программа аварийно завершается сигналом
"деление с плавающей точкой" (SIGFPE) — на аппаратном уровне x86 деление целых чисел на ноль вызывает
именно этот сигнал, и, в отличие от переполнения, UBSan здесь не может просто напечатать диагностику и
продолжить выполнение: само процессорное исключение уже произошло. Строка `printf("c = %d\n", c);` в этом
случае не выполняется вовсе. Это хорошая иллюстрация того, что UB не обязано быть "тихим": иногда оно
проявляется немедленным и заметным крахом программы, а не правдоподобным, но некорректным числом.

### Как защищаться от неопределённого поведения на практике

Правило простое: код никогда не должен *намеренно* полагаться на неопределённое поведение, а компилятор
следует настраивать так, чтобы он как можно раньше сообщал о потенциальных случаях UB. На практике это
означает: всегда компилировать с `-Wall -Wextra -Werror`, чтобы статически обнаружимые случаи (как в
примере с `i++, i++`) превращались в ошибку компиляции; при разработке и тестировании дополнительно
собирать программу с `-fsanitize=undefined` (а также, где уместно, `-fsanitize=address`), чтобы отлавливать
случаи UB, которые проявляются только во время выполнения на конкретных входных данных; и всегда проверять
входные данные и промежуточные результаты там, где переполнение, деление на ноль или выход за границы
теоретически возможны, а не полагаться на то, что "на практике такого не случится".
