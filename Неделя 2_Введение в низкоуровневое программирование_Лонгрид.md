## Несколько функций в одной единице компиляции

*Единица компиляции* (translation unit) &mdash; это результат препроцессирования одного файла с исходным
кодом на C: файл, в который подставлено содержимое всех файлов, подключённых директивами `#include`, и
которое затем целиком передаётся компилятору. Простейший способ организовать программу с несколькими
функциями &mdash; определить все функции в одном файле, то есть в одной единице компиляции.

Рассмотрим задачу: вычислить площадь и длину окружности круга заданного радиуса, используя две отдельные
функции.

```c
#include <stdio.h>

double circle_area(double radius)
{
    return 3.14159265358979 * radius * radius;
}

double circle_circumference(double radius)
{
    return 2 * 3.14159265358979 * radius;
}

int main(void)
{
    double radius = 5.0;
    printf("area = %.4f\n", circle_area(radius));
    printf("circumference = %.4f\n", circle_circumference(radius));
    return 0;
}
```

Здесь в одном файле определены три функции: `circle_area`, `circle_circumference` и `main`. Поскольку
все три функции находятся в одной единице компиляции, функции `circle_area` и `circle_circumference`
можно вызывать из `main` без отдельного объявления &mdash; достаточно, чтобы их определения находились
в файле выше по тексту, чем место вызова (компилятор C обрабатывает файл последовательно сверху вниз и
должен видеть определение или хотя бы объявление функции до её первого использования).

Скомпилируем и запустим программу:

```bash
gcc -Wall -Wextra -std=gnu17 geom_single.c -o geom_single
./geom_single
```

Результат работы программы:

```
area = 78.5398
circumference = 31.4159
```

## Несколько функций в разных единицах компиляции

Ту же самую задачу можно решить, разместив вспомогательные функции в отдельном файле. Тогда файл с
функцией `main` и файл с вспомогательными функциями компилируются как две независимые единицы компиляции,
а затем компоновщик (linker) объединяет получившиеся объектные файлы в одну исполняемую программу.

Чтобы одна единица компиляции могла вызывать функцию, определённую в другой единице компиляции, вызывающему
файлу нужно объявление (прототип) этой функции &mdash; определение самой функции в этом файле не требуется.
Объявления принято выносить в отдельный *заголовочный файл*, который подключается директивой `#include` во
все файлы, использующие эти функции, в том числе и в файл, где эти функции определены &mdash; это позволяет
компилятору сверить объявление с фактическим определением функции.

Заголовочный файл `geometry.h`:

```c
#ifndef GEOMETRY_H
#define GEOMETRY_H

double circle_area(double radius);
double circle_circumference(double radius);

#endif
```

Конструкция `#ifndef GEOMETRY_H` / `#define GEOMETRY_H` / `#endif` называется *include guard*
(защита от повторного включения). Она защищает от повторной обработки содержимого заголовочного файла,
если он окажется подключённым в одну единицу компиляции более одного раза, например через цепочку
других заголовочных файлов &mdash; без такой защиты повторные объявления одних и тех же функций привели
бы к ошибке компиляции.

Файл `geometry.c` с определениями функций:

```c
#include "geometry.h"

double circle_area(double radius)
{
    return 3.14159265358979 * radius * radius;
}

double circle_circumference(double radius)
{
    return 2 * 3.14159265358979 * radius;
}
```

Обратите внимание, что заголовочный файл здесь подключается с помощью кавычек `"geometry.h"`, а не угловых
скобок. Кавычки означают, что заголовочный файл ищется среди файлов текущего проекта, в отличие от угловых
скобок, которыми подключаются заголовочные файлы системных и внешних библиотек, например `<stdio.h>`.

Файл `main.c`, использующий функции из `geometry.c`:

```c
#include <stdio.h>
#include "geometry.h"

int main(void)
{
    double radius = 5.0;
    printf("area = %.4f\n", circle_area(radius));
    printf("circumference = %.4f\n", circle_circumference(radius));
    return 0;
}
```

Файл `main.c` подключает заголовочный файл `geometry.h`, поэтому компилятор, обрабатывая `main.c`, знает
сигнатуры функций `circle_area` и `circle_circumference`, даже несмотря на то, что сами эти функции
определены в другом файле. Скомпилировать и слинковать оба файла в одну программу можно одной командой:

```bash
gcc -Wall -Wextra -std=gnu17 main.c geometry.c -o geometry_demo
./geometry_demo
```

Результат работы программы:

```
area = 78.5398
circumference = 31.4159
```

Результат в точности совпадает с результатом программы из предыдущего раздела &mdash; поведение программы
не зависит от того, как исходный код распределён по файлам. Драйвер компиляции `gcc`, вызванный с двумя
файлами `.c`, разбивает работу на два независимых шага компиляции и заключительный шаг компоновки, но эти
шаги можно выполнить и по отдельности:

```bash
gcc -Wall -Wextra -std=gnu17 -c main.c -o main.o          # компилируем main.c в объектный файл
gcc -Wall -Wextra -std=gnu17 -c geometry.c -o geometry.o  # компилируем geometry.c в объектный файл
gcc main.o geometry.o -o geometry_demo                    # компонуем оба объектных файла в программу
```

На шаге компоновки компоновщик находит в файле `main.o` неопределённые ссылки на `circle_area` и
`circle_circumference`, а в файле `geometry.o` &mdash; их определения, и связывает их друг с другом,
формируя один исполняемый файл.

## Массивы: объявление, инициализация и работа с массивами

### Объявление и инициализация

Массив фиксированного размера объявляется указанием типа элементов и количества элементов в квадратных
скобках:

```c
int values[10];
```

Здесь объявлен массив `values` из 10 значений типа `int`. Если массив глобальный или статический, его
элементы по умолчанию инициализируются нулями; если массив локальный и не инициализирован явно, его
элементы содержат недетерминированные значения, как и обычные локальные переменные.

Массив можно инициализировать при объявлении несколькими способами:

```c
#include <stdio.h>

int main(void)
{
    int a[5] = {0};                 // все нули
    int b[5] = {1, 2, 3};           // первые три заданы, остальные - нули
    int c[] = {10, 20, 30};         // размер выведен из инициализатора - 3
    int d[5] = {[1] = 2, [3] = 3};  // отдельные элементы по индексу

    printf("a: "); for (size_t i = 0; i < 5; ++i) printf("%d ", a[i]); printf("\n");
    printf("b: "); for (size_t i = 0; i < 5; ++i) printf("%d ", b[i]); printf("\n");
    printf("c: "); for (size_t i = 0; i < sizeof(c)/sizeof(c[0]); ++i) printf("%d ", c[i]); printf("\n");
    printf("d: "); for (size_t i = 0; i < 5; ++i) printf("%d ", d[i]); printf("\n");
    printf("sizeof(c)/sizeof(c[0]) = %zu\n", sizeof(c)/sizeof(c[0]));
    return 0;
}
```

Результат работы программы:

```
a: 0 0 0 0 0 
b: 1 2 3 0 0 
c: 10 20 30 
d: 0 2 0 3 0 
sizeof(c)/sizeof(c[0]) = 3
```

Массив `a` полностью обнулён инициализатором `{0}`. У массива `b` заданы только первые три элемента,
остальные два неявно заполнены нулями &mdash; так работает частичная инициализация: если инициализатор
короче размера массива, недостающие элементы заполняются нулями. У массива `c` размер вообще не указан в
квадратных скобках &mdash; он выведен компилятором из количества элементов в инициализаторе, здесь это 3.
Массив `d` использует *инициализацию по индексу* (designated initializer): явно заданы только элементы с
индексами 1 и 3, остальные элементы &mdash; нули.

Количество элементов в массиве можно вычислить как отношение полного размера массива к размеру одного
элемента: `sizeof(arr) / sizeof(arr[0])`. Эта формула работает только для настоящих массивов, а не для
указателей &mdash; эта тема будет отдельно рассмотрена позже, при изучении указателей.

### Индексация и расположение в памяти

В языке C нумерация элементов массива начинается с 0: первый элемент массива `arr` &mdash; это `arr[0]`,
а не `arr[1]`. Соответственно, у массива из `n` элементов последний элемент &mdash; это `arr[n-1]`;
допустимые индексы лежат в диапазоне от `0` до `n-1` включительно, и обращение по индексу `n` или больше
&mdash; выход за границы массива.

Все элементы массива размещаются в памяти *непрерывно*, один сразу за другим, без каких-либо промежутков
между ними: адрес элемента с индексом `i` равен адресу начала массива плюс `i * sizeof(arr[0])` байт. Именно
из-за непрерывного размещения работает индексация `arr[i]` и указательная арифметика, о которой будет
рассказано в следующем разделе.

### Типичная ошибка: off-by-one

Одна из самых распространённых ошибок при работе с массивами &mdash; ошибка "на единицу" (off-by-one):
использование в условии цикла оператора `<=` вместо `<`, из-за чего цикл выполняет на одну итерацию больше,
чем нужно, и обращается к элементу с индексом `n`, которого не существует.

```c
#include <stdio.h>

int main(void)
{
    int values[5] = { 10, 20, 30, 40, 50 };

    for (int i = 0; i <= 5; ++i) {   // ОШИБКА: должно быть i < 5, а не i <= 5
        printf("values[%d] = %d\n", i, values[i]);
    }
    return 0;
}
```

У массива `values` пять элементов, значит допустимые индексы &mdash; от 0 до 4, но условие `i <= 5`
допускает и значение `i == 5`, для которого `values[5]` уже выходит за границы массива. Обращение к
элементу за границами массива &mdash; неопределённое поведение: оно не обязательно приведёт к заметной
ошибке сразу же, программа может "случайно" считать какие-то данные, расположенные в памяти сразу за
массивом, и продолжить работать как ни в чём не бывало, что делает такие ошибки особенно коварными и
трудными для обнаружения при обычном тестировании.

Скомпилируем эту программу с санитайзером адресов (`-fsanitize=address`) &mdash; специальным режимом
компиляции, который отслеживает каждое обращение к памяти во время работы программы и немедленно сообщает
о выходе за границы массива, вместо того чтобы позволить программе молча продолжить работу с некорректными
данными:

```bash
gcc -Wall -Wextra -std=gnu17 -fsanitize=address,undefined -g offbyone.c -o offbyone
./offbyone
```

Программа завершается аварийно с диагностикой:

```
offbyone.c:8:46: runtime error: index 5 out of bounds for type 'int [5]'
==12==ERROR: AddressSanitizer: stack-buffer-overflow on address ...
READ of size 4 at ... thread T0
    #0 ... in main /tmp/longread4/offbyone.c:8
```

Санитайзер точно указывает и на строку с ошибкой (`offbyone.c:8`), и на то, что происходит недопустимое
чтение за границами массива, размещённого на стеке (`stack-buffer-overflow`). Правильная версия цикла
использует строгое сравнение `i < 5` (или, ещё лучше, `i < n`, где `n` вычислено через
`sizeof(values) / sizeof(values[0])`, чтобы условие оставалось верным, даже если размер массива в
дальнейшем изменится), и тогда ошибка выхода за границы не возникает.

### Работа с массивом

Рассмотрим задачу: дан массив целых чисел, требуется найти его сумму, минимум, максимум и среднее
арифметическое.

```c
#include <stdio.h>

int main(void)
{
    int values[] = { 4, 8, 15, 16, 23, 42 };
    size_t n = sizeof(values) / sizeof(values[0]);

    int sum = 0;
    int min = values[0];
    int max = values[0];

    for (size_t i = 0; i < n; ++i) {
        sum += values[i];
        if (values[i] < min) min = values[i];
        if (values[i] > max) max = values[i];
    }

    printf("count = %zu\n", n);
    printf("sum = %d\n", sum);
    printf("min = %d, max = %d\n", min, max);
    printf("average = %.2f\n", (double) sum / n);
    return 0;
}
```

Результат работы программы:

```
count = 6
sum = 108
min = 4, max = 42
average = 18.00
```

Цикл проходит по массиву один раз, накапливая сумму и обновляя текущие минимум и максимум при каждом
элементе, который оказывается меньше текущего минимума или больше текущего максимума соответственно.
Обратите внимание, что переменная `n`, хранящая количество элементов, имеет тип `size_t`, а не `int`
&mdash; это правильный тип для индексации массивов и хранения их размера.

## Приоритет выполнения операций

Когда в одном выражении используется несколько операторов, порядок, в котором они применяются к операндам,
определяется *приоритетом операторов* (operator precedence) и их *ассоциативностью* (associativity, то есть
порядком применения операторов одного приоритета &mdash; слева направо или справа налево). Ниже приведена
таблица приоритета для операторов, наиболее часто встречающихся в простых программах, от самого высокого
приоритета к самому низкому. Операторы в одной строке таблицы имеют одинаковый приоритет.

| Приоритет | Операторы | Описание | Ассоциативность |
| - | - | - | - |
| 1 (высший) | `+x`, `-x`, `!x` | Унарный плюс, унарный минус, логическое отрицание | справа налево |
| 2 | `*`, `/`, `%` | Умножение, деление, остаток от деления | слева направо |
| 3 | `+`, `-` | Сложение, вычитание | слева направо |
| 4 | `<`, `<=`, `>`, `>=` | Операторы отношения | слева направо |
| 5 | `==`, `!=` | Равенство, неравенство | слева направо |
| 6 | `&` | Побитовое И | слева направо |
| 7 | `&&` | Логическое И | слева направо |
| 8 | `\|\|` | Логическое ИЛИ | слева направо |
| 9 | `= += -= *= /= %=` | Присваивание и составное присваивание | справа налево |

Чем выше оператор в этой таблице, тем раньше он выполняется в выражении без скобок. Например, в выражении
`a + b * c` умножение имеет более высокий приоритет, чем сложение, поэтому сначала вычисляется `b * c`, а
уже потом &mdash; сумма с `a`.

```c
#include <stdio.h>

int main(void)
{
    int a = 5, b = 10, c = 15;
    int result = a + b * c;   // умножение имеет более высокий приоритет, чем сложение
    printf("%d\n", result);
    return 0;
}
```

Результат работы программы:

```
155
```

Результат равен 155, то есть `5 + (10 * 15)`, а не 225, то есть не `(5 + 10) * 15`.

Одна из классических ошибок, связанных с приоритетом операторов в языке C &mdash; смешивание побитового
оператора `&` с оператором сравнения `==`. Оператор `==` имеет более высокий приоритет, чем `&`, поэтому
выражение `x & mask == 4` вычисляется как `x & (mask == 4)`, а вовсе не как `(x & mask) == 4`, что обычно
и имелось в виду.

```c
#include <stdio.h>

int main(void)
{
    int mask = 0x0F;
    int x = 4;

    if (x & mask == 4) {          // на самом деле: x & (mask == 4)
        printf("branch: then\n");
    } else {
        printf("branch: else\n");
    }

    if ((x & mask) == 4) {        // явные скобки - то, что имелось в виду
        printf("fixed branch: then\n");
    } else {
        printf("fixed branch: else\n");
    }
    return 0;
}
```

Здесь `mask` равен `0x0F`, то есть 15, значение `mask == 4` ложно и равно 0, а `x & 0` равно 0 &mdash; в
итоге ветка `if (x & mask == 4)` не выполняется, хотя по смыслу задачи ожидалось, что `x & mask` (то есть
`4 & 15`, что равно 4) действительно равно 4, и ветка `then` должна была выполниться. Вторая проверка,
`(x & mask) == 4`, с явно расставленными скобками, работает так, как и задумывалось.

Результат работы программы:

```
branch: else
fixed branch: then
```

Компилятор GCC способен диагностировать эту распространённую ошибку. Уже при компиляции с опцией `-Wall`
(без `-Werror`) на такое выражение будет выдано предупреждение:

```
prec2.c:10:18: warning: suggest parentheses around comparison in operand of '&' [-Wparentheses]
   10 |     if (x & mask == 4) {
      |             ~~~~~^~~~
```

Из-за подобных неочевидных случаев мы рекомендуем не полагаться на память о точном приоритете операторов,
особенно когда в одном выражении смешиваются операторы разных категорий (арифметические, побитовые,
логические, сравнения), а расставлять скобки явно &mdash; это делает намерение программиста однозначным
и для читателя кода, и для компилятора, а заодно защищает от ошибок вроде рассмотренной выше.

## Строки в языке C

Строка в языке C &mdash; это не отдельный встроенный тип, а обычный массив элементов типа `char`, в конце
которого лежит специальный *нулевой байт* `'\0'`, отмечающий конец строки. У строки нет отдельно хранимого
где-то ещё значения длины &mdash; всё, что определяет, где строка заканчивается, это позиция нулевого
байта в массиве. Раз строка &mdash; это массив, к ней применимо всё, что мы уже знаем о массивах: 0-индексация,
непрерывное расположение элементов в памяти, вычисление `sizeof`.

### Объявление и инициализация строк

Строку можно объявить и инициализировать так же, как любой другой массив &mdash; явным перечислением
элементов, включая завершающий нулевой байт:

```c
char greeting1[6] = {'H', 'e', 'l', 'l', 'o', '\0'};
```

Но гораздо удобнее и привычнее инициализировать массив символов *строковым литералом* &mdash; текстом в
двойных кавычках. В этом случае компилятор сам добавляет завершающий нулевой байт и, если размер массива не
указан явно, сам вычисляет нужный размер:

```c
char greeting2[] = "Hello";   // компилятор сам добавит завершающий '\0' и вычислит размер массива
```

```c
#include <stdio.h>

int main(void)
{
    char greeting1[6] = {'H', 'e', 'l', 'l', 'o', '\0'};
    char greeting2[] = "Hello";

    printf("greeting1 = \"%s\", sizeof = %zu\n", greeting1, sizeof(greeting1));
    printf("greeting2 = \"%s\", sizeof = %zu\n", greeting2, sizeof(greeting2));
    return 0;
}
```

Результат работы программы:

```
greeting1 = "Hello", sizeof = 6
greeting2 = "Hello", sizeof = 6
```

Оба массива в результате устроены совершенно одинаково: каждый занимает 6 байт, пять из которых &mdash;
буквы слова `Hello`, а шестой, последний &mdash; завершающий нулевой байт. Именно поэтому `sizeof` строки,
инициализированной литералом `"Hello"` (5 символов), равен 6, а не 5 &mdash; строковый литерал в языке C
всегда неявно включает завершающий нулевой байт, который тоже занимает место в массиве.

### Индексация строки и подсчёт длины вручную

Поскольку строка &mdash; это массив, к её символам можно обращаться по индексу точно так же, как к
элементам любого другого массива, и точно так же вычислять её длину, продвигаясь по индексам, пока не
встретится нулевой байт:

```c
#include <stdio.h>

int main(void)
{
    char word[] = "hello";

    int length = 0;
    while (word[length] != '\0') {
        ++length;
    }
    printf("word = \"%s\", length = %d\n", word, length);

    if (word[0] >= 'a' && word[0] <= 'z') {
        word[0] = (char) (word[0] - 'a' + 'A');
    }
    printf("capitalized: %s\n", word);

    return 0;
}
```

Результат работы программы:

```
word = "hello", length = 5
capitalized: Hello
```

Цикл `while (word[length] != '\0')` перебирает индексы `0, 1, 2, ...`, пока не встретит нулевой байт, и
считает количество пройденных индексов &mdash; это ровно длина строки, не считая самого нулевого байта.
Дальше символ `word[0]` изменяется напрямую, как обычный элемент массива: если это строчная латинская
буква, к её коду прибавляется разница кодов `'A'` и `'a'`, что превращает её в заглавную. Стандартная
библиотека C предоставляет для похожих задач готовые функции (например, `strlen` для подсчёта длины) &mdash;
мы рассмотрим их отдельно и подробнее, когда будем разбирать указатели и работу со строками через
стандартную библиотеку.

### Ввод и вывод строк

Спецификатор `%s` для `printf` и `scanf` мы уже видели раньше. Применительно к массиву символов важно одно
уточнение: имя массива, использованное без индексации, само по себе служит адресом его первого элемента,
поэтому при чтении строки функцией `scanf` перед именем массива не нужен оператор `&`, в отличие от чтения
обычной переменной вроде `int`. Подробнее о том, почему это так и как массивы связаны с указателями, будет
рассказано позже, при изучении указателей.

```c
#include <stdio.h>

int main(void)
{
    char name[32];
    printf("Enter your name: ");
    if (scanf("%31s", name) != 1) {   // без & перед name - имя массива уже само является адресом
        fprintf(stderr, "input error\n");
        return 1;
    }
    printf("Hello, %s!\n", name);
    return 0;
}
```

Если на вход подать `Katerina`, программа выведет:

```
Enter your name: Hello, Katerina!
```

Как и в примере с `%7s` из предыдущего файла, ширина поля `%31s` ограничивает число считываемых символов
тридцатью одним, оставляя место для завершающего нулевого байта в 32-байтном массиве `name` &mdash; без
этого ограничения слишком длинный ввод привёл бы к записи за пределы массива.
