# Разработка на языке C в Linux: от установки до отладки

## Краткий обзор

В этом разделе мы пройдём весь путь настройки окружения для разработки на языке C в Linux и научимся
пользоваться основными инструментами.

Во-первых, мы установим Visual Studio Code &mdash; текстовый редактор с поддержкой подсветки синтаксиса
C и встроенным терминалом, в котором удобно писать код.

Во-вторых, мы установим сам компилятор GCC, без которого написанный код нельзя превратить в исполняемую
программу.

В-третьих, мы разберём, как компилировать программу из командной строки, и рассмотрим самые популярные
опции компилятора `gcc`.

В-четвёртых, мы рассмотрим, как запускать скомпилированные программы, передавать им аргументы командной
строки и перенаправлять потоки ввода-вывода.

В-пятых, мы рассмотрим отладку программ: интерактивный отладчик `gdb`, который позволяет пошагово выполнять
программу и исследовать её состояние, и *санитайзеры* &mdash; специальный режим компиляции, который находит
ошибки работы с памятью и неопределённое поведение прямо во время выполнения программы.

Сразу отметим важный момент, характерный для разработки на языке C: несмотря на то, что мы будем
использовать текстовый редактор с удобным интерфейсом, сама компиляция, запуск и отладка программ будут
выполняться из командной строки, а не через кнопки редактора. Работа в командной оболочке &mdash; это
базовый навык системного программирования, который необходимо освоить в любом случае, и удобнее сразу
привыкнуть к нему, чем полагаться на скрытую от глаз автоматизацию интегрированной среды разработки.

## Установка Visual Studio Code

Visual Studio Code (VS Code) &mdash; бесплатный текстовый редактор с открытым исходным кодом, широко
используемый для разработки на самых разных языках программирования, в том числе на C. В контексте этого
курса он используется как удобный редактор кода с подсветкой синтаксиса, автодополнением и встроенным
терминалом &mdash; не как полноценная интегрированная среда разработки с автоматической сборкой проекта.

Самый надёжный способ установить VS Code на Debian-совместимый дистрибутив Linux (Ubuntu, Debian и
производные) &mdash; подключить официальный репозиторий Microsoft и установить пакет через `apt`:

```bash
sudo apt-get update
sudo apt-get install -y wget gpg
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor > packages.microsoft.gpg
sudo install -D -o root -g root -m 644 packages.microsoft.gpg /etc/apt/keyrings/packages.microsoft.gpg
sudo sh -c 'echo "deb [arch=amd64,arm64,armhf signed-by=/etc/apt/keyrings/packages.microsoft.gpg] https://packages.microsoft.com/repos/code stable main" > /etc/apt/sources.list.d/vscode.list'
sudo apt-get update
sudo apt-get install -y code
```

Такой способ (в отличие от разового скачивания `.deb`-файла с сайта) удобен тем, что дальнейшие обновления
редактора будут приходить вместе с обычными обновлениями системы через `apt upgrade`.

Более простой, но разовый способ &mdash; скачать `.deb`-пакет с официального сайта
[code.visualstudio.com](https://code.visualstudio.com) и установить его напрямую:

```bash
sudo apt install ./code_*.deb
```

После установки редактор запускается командой `code`, а с указанием каталога проекта &mdash; командой
`code .` (запустит редактор с текущим каталогом, открытым как проект).

Для удобной работы с кодом на C стоит установить расширение **C/C++** от Microsoft (идентификатор
`ms-vscode.cpptools`) &mdash; оно добавляет подсветку синтаксиса, автодополнение имён и переход к
определениям функций и переменных. Установить расширение можно через встроенный магазин расширений
редактора (значок в левой боковой панели) или командой:

```bash
code --install-extension ms-vscode.cpptools
```

Встроенный терминал редактора открывается сочетанием клавиш Ctrl+` (обратная кавычка) или через меню
`Terminal -> New Terminal`. Именно в нём и будут выполняться все команды из следующих разделов &mdash;
компиляция, запуск и отладка программ.

## Установка компилятора GCC

Собственно превращает исходный код на C в исполняемую программу не редактор, а отдельная программа
&mdash; компилятор. В этом курсе используется GNU Compiler Collection (GCC).

На Debian-совместимых дистрибутивах (Ubuntu, Debian) удобнее всего установить не отдельно `gcc`, а сразу
пакет `build-essential`, который включает в себя сам компилятор `gcc`, компилятор C++ `g++`, утилиту сборки
`make` и другие базовые инструменты разработки:

```bash
sudo apt update
sudo apt install -y build-essential
```

На дистрибутивах на основе Fedora/RHEL используется менеджер пакетов `dnf`:

```bash
sudo dnf groupinstall -y "Development Tools"
```

На Arch Linux и его производных:

```bash
sudo pacman -S base-devel
```

Отладчик `gdb`, о котором пойдёт речь ниже, в пакет `build-essential` не входит, его нужно устанавливать
отдельно:

```bash
sudo apt install -y gdb
```

После установки стоит проверить, что компилятор действительно доступен из командной строки, и посмотреть
его версию:

```bash
gcc --version
```

Пример вывода этой команды:

```
gcc (Ubuntu 11.4.0-1ubuntu1~22.04.3) 11.4.0
Copyright (C) 2021 Free Software Foundation, Inc.
```

Точная версия компилятора и текст вывода будут отличаться в зависимости от установленного дистрибутива и
даты установки, но важно, что команда в принципе отрабатывает без ошибки `command not found` &mdash; это
означает, что компилятор успешно установлен и находится в переменной окружения `PATH`.

## Компиляция в командной строке: опции gcc

### Базовая компиляция

Самый простой вариант вызова компилятора выглядит так:

```bash
gcc prog.c -o prog
```

Компилятор берёт файл `prog.c`, компилирует его, и, если ошибок нет, записывает готовый исполняемый файл
с именем `prog`. Без опции `-o` исполняемый файл будет назван `a.out` &mdash; по историческим причинам,
уходящим корнями в самые первые версии Unix.

### Рекомендуемая командная строка

На практике одной простой команды недостаточно &mdash; стоит сразу включать дополнительную диагностику и
предупреждения компилятора, чтобы ловить ошибки на этапе компиляции, а не при запуске программы:

```bash
gcc -Wall -Wextra -Werror -std=gnu17 -g prog.c -o prog
```

### Таблица популярных опций

| Опция | Назначение |
| - | - |
| `-o FILE` | Записать результат компиляции (или сборки) в файл `FILE` |
| `-c` | Только скомпилировать в объектный файл `.o`, не выполнять компоновку |
| `-Wall` | Включить основные предупреждения компилятора о потенциальных ошибках |
| `-Wextra` | Включить дополнительные предупреждения, не входящие в `-Wall` |
| `-Werror` | Считать все предупреждения ошибками компиляции |
| `-std=STD` | Использовать конкретный стандарт языка, например `gnu17` или `c17` |
| `-g` | Добавить в исполняемый файл отладочную информацию (нужна для `gdb`) |
| `-O0`, `-O2` | Уровень оптимизации: `-O0` &mdash; без оптимизаций (удобно для отладки), `-O2` &mdash; с оптимизациями (для готовой программы) |
| `-I PATH` | Добавить каталог `PATH` к списку мест поиска заголовочных файлов |
| `-L PATH` | Добавить каталог `PATH` к списку мест поиска библиотек |
| `-lNAME` | Слинковать программу с библиотекой `NAME` (например, `-lm` для математической библиотеки) |
| `-fsanitize=address,undefined` | Включить санитайзеры (см. раздел про отладку ниже) |

Убедимся, что рекомендуемая командная строка действительно работает, на простой программе:

```bash
cat > prog.c << 'EOF'
#include <stdio.h>

int main(void)
{
    printf("Hello from GCC!\n");
    return 0;
}
EOF
gcc -Wall -Wextra -Werror -std=gnu17 -g prog.c -o prog
./prog
```

Результат:

```
Hello from GCC!
```

Если исходный код состоит из нескольких файлов, все их можно перечислить в одной команде компиляции:

```bash
gcc -Wall -Wextra -Werror -std=gnu17 -g main.c helper.c -o prog
```

## Запуск программ

Скомпилированный исполняемый файл запускается указанием пути к нему. Если файл находится в текущем
каталоге, путь начинается с `./`, потому что современные командные оболочки Linux, в отличие от Windows,
из соображений безопасности не ищут исполняемые файлы в текущем каталоге автоматически:

```bash
./prog
```

Аргументы командной строки передаются программе просто через пробел после имени программы:

```bash
./prog foo bar
```

Программа, которая выводит полученные аргументы:

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    printf("argc = %d\n", argc);
    for (int i = 0; i < argc; ++i) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }
    return 0;
}
```

Результат запуска `./prog foo bar`:

```
argc = 3
argv[0] = ./prog
argv[1] = foo
argv[2] = bar
```

Код завершения только что отработавшей программы можно посмотреть командой `echo $?`; 0 означает успешное
завершение, любое другое значение &mdash; сигнал об ошибке.

Стандартные потоки ввода, вывода и ошибок можно перенаправлять с помощью операторов `<`, `>` и `2>`:

```bash
./prog < input.txt > output.txt 2> errors.txt
```

Здесь `<` перенаправляет содержимое файла `input.txt` на стандартный поток ввода программы, `>` записывает
стандартный поток вывода в файл `output.txt` (перезаписывая его содержимое), а `2>` отдельно перенаправляет
поток ошибок в файл `errors.txt`.

## Отладка

### GDB: интерактивный отладчик

GDB (GNU Debugger) &mdash; интерактивный отладчик, который позволяет запустить программу под своим
контролем: приостанавливать её выполнение в заданных местах, выполнять её пошагово, инспектировать значения
переменных и просматривать стек вызовов функций в момент остановки или аварийного завершения программы.
Чтобы отладчик мог сопоставлять машинный код с исходным текстом программы (показывать номера строк, имена
переменных и так далее), программу нужно скомпилировать с опцией `-g`, добавляющей отладочную информацию в
исполняемый файл.

Отладчик запускается командой `gdb`, которой передаётся имя исполняемого файла:

```bash
gdb ./prog
```

После запуска отладчик выводит собственное приглашение `(gdb)`, в котором можно вводить команды отладчика.
Самые часто используемые команды перечислены в таблице ниже.

| Команда | Сокращение | Назначение |
| - | - | - |
| `run [аргументы]` | `r` | Запустить программу (с указанными аргументами командной строки, если нужны) |
| `break МЕСТО` | `b` | Установить точку останова (breakpoint) на функции или строке, например `break main` или `break prog.c:10` |
| `next` | `n` | Выполнить следующую строку исходного кода, не заходя внутрь вызываемых функций |
| `step` | `s` | Выполнить следующую строку исходного кода, заходя внутрь вызываемых функций |
| `continue` | `c` | Продолжить выполнение программы до следующей точки останова или до её завершения |
| `print ВЫРАЖЕНИЕ` | `p` | Вывести значение переменной или выражения |
| `backtrace` | `bt` | Показать стек вызовов функций в текущей точке остановки |
| `list` | `l` | Показать исходный код вокруг текущей строки |
| `quit` | `q` | Выйти из отладчика |

Типичный сеанс отладки выглядит так: сначала устанавливается точка останова на интересующей функции или
строке (`break main`), затем программа запускается командой `run`; выполнение автоматически
приостанавливается, как только доходит до точки останова. Дальше можно выполнять программу пошагово
командами `next` и `step`, в любой момент печатать значения переменных командой `print имя_переменной`, а
если программа уже успела аварийно завершиться (например, из-за разыменования нулевого указателя), команда
`backtrace`, выполненная сразу после падения, покажет цепочку вызовов функций, которая привела к ошибке,
включая номера строк исходного кода &mdash; это часто самый быстрый способ найти место в программе, где
что-то пошло не так.

### Санитайзеры

Санитайзеры &mdash; это специальный режим компиляции, при котором компилятор окружает потенциально опасные
операции дополнительными проверками прямо на этапе генерации машинного кода, а при выполнении программы эти
проверки отслеживают каждое подозрительное обращение к памяти или каждую потенциально некорректную
арифметическую операцию. В отличие от `gdb`, который требует, чтобы пользователь сам догадался, где
остановить программу и что посмотреть, санитайзер обнаруживает ошибку автоматически, в момент её
возникновения, и сразу сообщает точное место в коде.

Санитайзеры включаются опцией компилятора `-fsanitize=`, чаще всего в сочетании `address,undefined`:
`AddressSanitizer` находит ошибки работы с памятью (выход за границы массива, использование уже
освобождённой памяти, двойное освобождение), а `UndefinedBehaviorSanitizer` находит другие виды
неопределённого поведения (переполнение знаковых целых чисел, разыменование некорректно выровненных
указателей и подобное).

Рассмотрим ошибку использования уже освобождённой памяти (use-after-free):

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *p = malloc(sizeof(int));
    *p = 42;
    free(p);
    printf("%d\n", *p);  // use-after-free
    return 0;
}
```

Скомпилируем и запустим программу с санитайзером адресов:

```bash
gcc -Wall -Wextra -std=gnu17 -fsanitize=address -g uaf.c -o uaf
./uaf
```

Программа завершается аварийно со следующей диагностикой:

```
==25==ERROR: AddressSanitizer: heap-use-after-free on address 0x502000000010 at pc 0x611d6d5c12e7 bp 0x7ffc8466bbc0 sp 0x7ffc8466bbb0
READ of size 4 at 0x502000000010 thread T0
    #0 0x611d6d5c12e6 in main /tmp/setupdoc/uaf.c:9

0x502000000010 is located 0 bytes inside of 4-byte region [0x502000000010,0x502000000014)
freed by thread T0 here:
    #0 ... in main /tmp/setupdoc/uaf.c:8

previously allocated by thread T0 here:
    #0 ... in main /tmp/setupdoc/uaf.c:6

SUMMARY: AddressSanitizer: heap-use-after-free /tmp/setupdoc/uaf.c:9 in main
```

Санитайзер не просто сообщает, что где-то в программе есть ошибка &mdash; он точно указывает строку 9,
где произошло недопустимое чтение уже освобождённой памяти, строку 8, где память была освобождена, и
строку 6, где эта память изначально была выделена. Такая диагностика в подавляющем большинстве случаев
сразу указывает на причину ошибки, без необходимости запускать интерактивный отладчик.

Рассмотрим ещё один пример &mdash; переполнение знакового целого числа, которое санитайзер адресов не
отслеживает, но которое ловит `UndefinedBehaviorSanitizer`:

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    volatile int x = INT_MAX;
    x = x + 1;   // signed overflow - неопределённое поведение
    printf("%d\n", x);
    return 0;
}
```

```bash
gcc -Wall -Wextra -std=gnu17 -fsanitize=undefined -g ubsan.c -o ubsan
./ubsan
```

Результат:

```
ubsan.c:7:11: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
-2147483648
```

В отличие от санитайзера адресов, `UndefinedBehaviorSanitizer` по умолчанию не прерывает программу после
обнаружения ошибки, а лишь сообщает о ней и продолжает выполнение (что и произошло выше: после сообщения об
ошибке программа всё равно допечатала значение `-2147483648`, полученное в результате переполнения). Чтобы
санитайзер прерывал программу сразу после первой обнаруженной ошибки, добавьте опцию
`-fno-sanitize-recover`.

Программу, скомпилированную с санитайзерами, из-за дополнительных проверок при каждом обращении к памяти
и при каждой потенциально опасной операции, полезно совмещать с отладчиком `gdb`: если санитайзер прерывает
выполнение программы, отладчик, запущенный на этом же исполняемом файле, покажет полный стек вызовов и даст
возможность исследовать значения всех переменных в момент, непосредственно предшествовавший ошибке.
